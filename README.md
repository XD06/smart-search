# Smart Search

> 一套**问题驱动的搜索方法论 Skill**，不是"要不要搜"的开关，而是一个搜索操作系统。

它解决的核心问题：AI 有搜索工具，却经常搜得浅、信得早、答得没有溯源。Smart Search 用一套强制流程把"搜索"变成"取证"——**先想需要什么证据，再想证据在哪，最后先填表再写答案**。

---

## 它和"直接搜一下"有什么区别

| 常见做法 | Smart Search |
|---|---|
| 拿到问题直接想关键词 | 先拆"要回答这题需要哪些证据"，再决定去哪找 |
| 所有信息去同一个地方搜 | 按信息类型匹配信源（定价→官网，体验→社区，Bug→Issue） |
| 搜到就用，不看出处时间 | 强制时间门禁，超时/无时间的数据直接丢弃 |
| 把用户转述当既定前提 | 转述默认视为未验证假设，先拆解再核查 |
| 拿用户原话整句搜索 | 提取"实体+数字"绕回一手信源，禁止回声室式伪验证 |
| 凭记忆补细节 | 先写证据表，表里没有的数据禁止出现在答案里 |

## 三个真正有增量的设计

### 1. 输入分型：用户给你的是问题，还是一段说法？

- **A 型 直接提问**（"X 多少钱"）→ 走五阶段主流程
- **B 型 信息投喂**（"据说…"、"看到一个帖子"）→ 先走**阶段 0 声称拆解**，把一段话拆成「立即核查的字面声称」和「暂存不查的暗含推测」
- **C 型 混合** → 按 A 型走，转述部分降级为待核查背景

这是大多数搜索流程的盲区：**用户转述的内容默认被当成了前提**。

### 2. 证据表：物理屏障，锁死训练记忆幻觉

结束搜索、开始写答案之前，**必须强制先写一张证据表**：

| # | 声明 | 来源 1 | 时间 | 来源 2 | 时间 | 验证状态 |
|---|------|--------|------|--------|------|---------|
| 1 | 定价 $20/月 | 官网 pricing | 2026-06 | 第三方报道 | 2026-05 | ✅ 交叉验证一致 |
| 2 | 某功能可用 | 官方 docs | 2026-05 | — | — | ❌ 单源，需标注 |
| 3 | （脑海里的记忆数据） | — | — | — | — | ❌ 无来源，禁止输出 |

**规则：表里没有的数据，禁止出现在最终答案中。** 写答案时发现某数据不在表里，说明它来自训练记忆，必须回炉验证。

### 3. 回声室规避：多篇二手搬运 ≠ 独立验证

核查转述说法时最大的风险不是搜不到，而是**搜到的全是同一说法的搬运**：

- ❌ 拿用户原话整句搜索 → 只能找到复读同一说法的自媒体
- ✅ 从声称中提取**实体 + 数字/规则**，绕回一手信源验证
- 社区帖只用于回答"实际体验和口径差异"，**不用于确认事实存否**
- 一手信源找不到时，宁可标注「无法独立证实」，**不得用多篇二手搬运互相"交叉验证"**——那是同一信源的复读，不是独立来源

## 目录结构

```
smart-search/
├── SKILL.md                      # 主文件：三层结构（Core Loop / Policy / Reference）
└── references/
    ├── claim-breakdown.md        # B 型输入拆解指南 + 五层完整示例
    ├── claim-examples.md         # 更多拆解实例（价格对比型、负面避坑型）
    ├── community-forums.md       # 中文/国际社区定向搜索速查表
    └── output-templates.md       # 输出模板 A~E（对比/单事实/评测/调研/核查）
```

**SKILL.md 的三层结构**：

| 层级 | 内容 |
|---|---|
| Level 1 Core Loop | 预判 → 输入分型 → 阶段 0~5（规划/收集/时效验证/证据表/输出） |
| Level 2 Policy | 信息源匹配、时间门禁阈值、软文甄别、矛盾处理、证据表规范、声称类型学、回声室规避 |
| Level 3 Reference | 社区速查表、输出模板、拆解工作台（按需加载） |

## 核心策略速览

**信息源匹配**（每种事实去最擅长产出它的地方）：

| 信息类型 | 首选 | 次选 |
|---|---|---|
| 定价 / 套餐 / 额度 | 官网 Pricing 页 | 官方文档 |
| API 参数 / 官方特性 | 官方 Docs | GitHub 示例 |
| Bug / 稳定性 | GitHub Issue | Reddit |
| 真实体验 / 避坑 | 社区（Reddit/V2EX/Linux DO） | X (Twitter) |
| 企业采购 / 架构选型 | Hacker News | 技术博客 |
| 商业数据 / 市值 | 财报 / 交易所 / 研报 | 权威财经媒体 |

**时间门禁**（旧数据比没数据更危险）：

- 定价 / 订阅费用：**3 个月**内
- 产品功能 / Benchmark：**6 个月**内
- 使用教程 / 评测体验：**12 个月**内
- 行业趋势 / 格局：**18 个月**内
- 技术原理 / 算法基础：**24 个月**内

## 安装

把本目录放到你的 Agent Skill 加载路径下即可。例如：

```powershell
# opencode
#   将 smart-search 整个目录放入 <config>/skills/
# 其他 Agent 工具
#   放入其约定的 skills 目录
```

若需要多个工具共用同一份文件（避免副本漂移），可用目录联接（Junction）指向本目录——**Windows 下 Junction 无需管理员权限，符号链接需要**：

```powershell
New-Item -ItemType Junction -Path "<另一个入口>\skills\smart-search" -Target "<本目录>"
```

## 设计理念

> 在开始搜索之前，**永远不要先想"搜索什么关键词"，而是先思考"要回答这个问题，需要哪些具体的证据？每一种证据最可能存在于哪里？"**

Smart Search 不是僵化的"先搜 A 再搜 B"说明书，而是问题驱动的搜索操作系统。它的约束都指向同一件事：**让每个结论都能追溯到具体来源和具体时间。**
