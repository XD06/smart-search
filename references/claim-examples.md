# 拆解实例库

`claim-breakdown.md` 是方法论 + 实例 1（推荐型转述，五层完整标准格式）；本文件补充其他输入类型的实例，格式同为五层：**"字面信息"是主线程立即查，"暗含/不为人知/推测/意图"是副线程暂存**。

> ⚠️ **以下实例中的具体价格、版本号、说法均为虚构演示内容**，不是真实事实，禁止当作已知事实引用。

## 实例 2：价格对比类转述

### 输入

> V2EX 上有人说 Cursor 一年 60 刀还无限用 Claude 4.5，比单独订 Claude Pro 划算多了。

### 一、字面信息（主线程）

| 声明 | 核查点 |
|------|--------|
| Cursor 订阅 $60/年 | 官网 Pricing 当前价格，注意年付/月付口径 |
| "无限用 Claude 4.5" | "无限"的真实条款：速率限制、每周上限、是否给到最新档模型 |
| "比 Claude Pro 划算" | 比较级：双方一手数据拉齐（价格 + 实际可得用量）再比 |

### 二、表面暗含（副线程）

说话者在做**订阅选型**：已经在为 AI 工具付费，想找更便宜的姿势。他的真实问题很可能是"我这个月要不要换/降级订阅"。

### 三、不为人知的一面（副线程）

- "无限"通常有速率上限，重度使用时排队或降智
- "无限用 4.5"和 Claude Pro 的 Claude Code 编程能力**不是一回事**——两个订阅解决的需求可能不重合
- Cursor 对自有模型与第三方模型的调用分配优先级
- 年付与月付的真实价差、退款政策

### 四、推测的信息（副线程）

- 国内网络环境下的可用性与支付渠道
- 合租/共享订阅的封号风险
- 同类"低价无限订阅"的历史翻车案例

### 五、用户想获得什么（副线程）

1. 这个价格是不是真的
2. 两个订阅覆盖的需求能否互相替代
3. 换过去有什么坑（限流、封号、退款）

## 实例 3：负面/避坑类转述

### 输入

> 群里都在说免费中转 API 迟早跑路，充的钱全都打水漂，千万别用。

### 一、字面信息（主线程）

| 声明 | 核查点 |
|------|--------|
| "中转 API 会跑路" | 现象类声称：找真实案例（社区翻车帖、公告、媒体报道），不能只有情绪帖 |
| "充的钱打水漂" | 具体案例与损失规模，需有据可查的佐证 |
| "都/迟早"（全称判断） | 逻辑上**一个反例即可部分证伪**——核查是否存在长期稳定的正规中转 |

### 二、表面暗含（副线程）

说话者在寻求**群体共识与风险确认**：要么已经踩坑，要么准备用中转 API 想听劝。情绪浓度高于信息浓度——核查要贴着原文走，不被情绪带着跑。

### 三、不为人知的一面（副线程）

- 中转 API 的商业模式：上游账号/key 批发的差价，低价背后往往是共享或灰色渠道
- 跑路的典型前兆：价格明显低于成本、不支持退款、无备案主体、只做一次性生意
- 正规渠道的等价方案：官方开发者计划、大厂模型的免费额度

### 四、推测的信息（副线程）

- 用户真正需要的可能是"如何安全地使用第三方 API"的操作性知识，而不是情绪确认
- 若已有充值，维权渠道和止损方式

### 五、用户想获得什么（副线程）

1. 这个说法是否成立（全称判断 vs 概率事实）
2. 已经在用的钱会不会打水漂、要不要撤
3. 有没有正规替代方案

## 实例速查对照

| 输入特征 | 走法要点 |
|----------|----------|
| 推荐型（"被低估/好用"） | 字面查实体+数字；观点查证据基 |
| 价格对比型（"比 X 划算"） | 双方一手数据拉齐；"无限/不限"必查口径 |
| 负面避坑型（"都/千万别"） | 警惕全称判断，主动找反例；默认找结构性原因而非个案 |
